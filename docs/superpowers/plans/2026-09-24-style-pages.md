# Style Showcase Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Thirty self-contained HTML showcase pages, one per city style study, each built in its own style, plus an index.

**Architecture:** A generated `styles-data.js` (from manifests, via the existing
`style_studies.py`) and a small shared `page-kit/` feed thirty independent
`styles/NN-slug/page/index.html` files. A pinned Playwright checker verifies each
page. No build step, no network at runtime.

**Tech Stack:** HTML/CSS/vanilla JS; Python 3 stdlib (generator/tests); Node +
pinned Playwright (verification only); vendored three.js and open-licence fonts.

**Spec:** `docs/superpowers/specs/2026-09-24-style-pages-design.md`

## Global Constraints

- Pages work from `file://` and `python3 -m http.server`; scripts load by `<script src>`, never `fetch`.
- No runtime request leaves the local origin: no CDN, remote fonts or analytics.
- Each page's own files ≤ 400 KB excluding sheets and shared vendor/fonts.
- Seven core-content items reachable by keyboard on every page; games add a "Read the notes" control.
- Sheets labelled as concept studies; `review_summary` shown verbatim; only 02 mentions selection.
- 28–30 keep "-inspired" framing; no authenticity claims.
- 375 px and 1440 px widths, no page-level horizontal scroll; `prefers-reduced-motion` honoured; zero console errors.
- Do not modify manifests, sheets, briefs, prompts, reviews or generated READMEs by hand.

## Review Focus

- Opening a page from disk (`file://`): must render fully; checker loads every page via `file://`.
- Phone width 375 px: no horizontal page scroll; checker measures `scrollWidth`.
- Keyboard-only reader on a game page: notes control is focusable and reveals all core content; checker asserts the `[data-core]` markers.
- Manifest selection changes later: pages must follow; `--check` flags a stale `styles-data.js` (Task 1 test).
- Reduced motion: no autoplaying heavy animation; checker screenshots with reduced motion emulated for review.

### Task 2: Page kit, vendored assets and checker

**Files:**
- Create: `docs/vision/style-studies/shared/page-kit/project.js`, `kit.js`, `README.md`, `vendor/three/` (+LICENSE), `fonts/<family>/` (+licences)
- Create: `scripts/style_pages/package.json`, `package-lock.json`, `check_pages.mjs`, `.gitignore`

**Interfaces:**
- `window.AGENTNAGAR = {name, tagline, summary: [paragraphs], firstSlice, facts: [..], links: {readme, decisions, prototype}}`
- `kit.js` exposes `window.Kit = {style(id) -> STYLE_DATA entry, sheetImg(style, sheetIndex, panel?) -> HTMLElement, navLinks(style) -> {prev, next, index} hrefs relative to the page, mountNav(el, style), notes(style, extra) -> HTMLElement}`.
  `panel` is one of `tl,tr,bl,br`; cropping uses a wrapper with `overflow:hidden` and a scaled, offset `<img>` computed from the contract's 20 px matte, 12 px gutter, 44 px footer, 32 px caption.
- Core markers: every page marks its sections with `data-core="project|style|views|agents|tradeoffs|status|nav"`.
- Checker: `node scripts/style_pages/check_pages.mjs [ids…]` → for each page loads `file://`, collects console errors and non-file requests, asserts seven `data-core` markers and resolvable nav hrefs, measures overflow at 375 px, writes screenshots to `.local/style-pages/<id>-{desktop,mobile,reduced}.png`, exits non-zero on failure.

- [ ] Step 1: Install pinned `playwright` and `three` in `scripts/style_pages/`; copy `three.module.min.js` + LICENSE into vendor; install fonts via `@fontsource/*` and copy woff2 + LICENSE.
- [ ] Step 2: Write `project.js` from README/VISION_DECISIONS facts only.
- [ ] Step 3: Write `kit.js`; write checker.
- [ ] Step 4: Build a throwaway fixture page in the scratchpad, run the checker against it, confirm pass and a forced failure (missing marker).
- [ ] Step 5: Commit.
