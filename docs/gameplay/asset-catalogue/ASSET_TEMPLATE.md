# Individual asset authoring template

[Catalogue](README.md) · Copy this template when a specific asset enters design.

An authored specification must replace the prompts below with concrete decisions or explicitly deferred choices. This template is not a completed production asset.

## Identity and description

Record the catalogue kind ID, definition ID/version, name, purpose, visual character, target locations, creator, source and usage rights. Describe how users distinguish it from similar objects.

## Physical characteristics

Specify dimensions and units, footprint, pivot, collision, handling class, grip/seat/entry/mount points, accepted surfaces, rotation, navigation clearance and attachment compatibility.

## Behavior and state

For each action, record the actor, permission, prerequisites, state before/after, cancellation and visible feedback. Separate proposed scenery, on-demand interaction and ongoing activity. State which fields persist and how occupied or interrupted use is released.

## Ownership, storage and trade

Specify the owner, borrowing/shared-use grants, portability, size/capacity rules, valid containers, contents visibility, transfer eligibility and sale contents. Explain how failed placement, full storage and concurrent action leave the item consistent. If linked to information or a service, specify the separate access check.

## Presentation and accessibility

Specify the first visual style, essential silhouette, materials, map/distant/close representations, required animations, sound, labels and non-color feedback. Identify invariant geometry across later style variants. Provide non-drag and non-gesture action alternatives.

## Device and production requirements

List required detail variants, unloaded/storage representation, expected scene density, source and export artifacts, dependency versions, packaging and compatibility requirements. Set measurable budgets after prototype evidence; do not copy an arbitrary budget from unrelated assets.

## Acceptance scenarios

Describe normal use, denied use, storage/placement failure, interruption/reconnect, simultaneous requests, ownership transfer and style/device changes as applicable. Verify both behavior and visual readability. Record evidence separately from intended behavior.
