# AI 3D asset generation (text-to-3D and image-to-3D) for a stylised real-time game — state as of 2026-10-01

Researcher notes. Every page was fetched on **2026-10-01** unless another date is given; "vendor claim" marks statements that come only from the seller. Prices and versions belong to that date.

Method limits that affect confidence: the session's web-search budget ran out part-way through this assignment, so discovery after that point used direct fetches of vendor documentation, terms pages, GitHub/Hugging Face/npm/arXiv APIs and pages already found. Vendor facts, licence text, prices and open-model requirements are therefore well covered from primary sources. **Independent practitioner evidence (Reddit, YouTube, 80.lv, CG Channel) is thin and is called out as a gap** in the last two sections. Nothing was installed, no model was downloaded or run, and no credits were spent. Licence readings below are a researcher's reading of the quoted text, not legal advice.

## 1. Leading hosted generators and open models: current versions, capabilities, automation, price, output licence

### Takeaway
Four hosted services are current, documented and scriptable — **Meshy 7.1** (plus the low-poly "Smart Topology" model `meshy-t2`), **Tripo v3.1 / P1 / P2**, **Rodin Gen-2.5** and **Tencent Hunyuan 3D 3.0/3.1** — each with face-count control, quad or low-poly modes, PBR textures and part splitting (Meshy, Tripo and Hunyuan also sell auto-rigging), at roughly **US$0.20–1.30 per generated asset**; Meshy, Tripo and Rodin all ship an official MCP server and Meshy and Tripo ship agent-oriented CLIs. For a public CC BY-SA repository the decisive facts are in the terms: **free tiers do not give you the rights you need** (Meshy keeps ownership and grants CC BY 4.0; Tripo retains all rights and marks free output non-commercial and public; Sloyd's free tier is personal-use only), whereas **paid Meshy and paid Tripo assign the output rights to the customer**, Rodin says it "will not limit your use", and Sloyd allows redistribution only on its US$50 Pro plan.

#### Meshy — capabilities, automation, price, terms
- Polygon/topology control: `topology` = `quad` ("quad-dominant mesh") or `triangle`; remesh `target_polycount` "Range 100 to 300,000, default 30,000"; Smart Topology `meshy-t2` gives "cleaner topology, natively separated parts, triangle output, and a face count you can set with target_polycount", "Range 100 to 15,000, default 4,000", triangle-only; `geometry_resolution` `standard`/`2k`/`4k` (Meshy 7.1 only); `pose_mode` `a-pose`/`t-pose`; output formats include glb, obj, fbx, stl, usdz — [Meshy text-to-3D API](https://docs.meshy.ai/en/api/text-to-3d).
- The old `art_style` switch (`realistic`, `sculpture`) is deprecated and "Not supported by Meshy-6"; no seed parameter is documented for text-to-3D or image-to-3D — [Meshy text-to-3D API](https://docs.meshy.ai/en/api/text-to-3d), [Meshy image-to-3D API](https://docs.meshy.ai/en/api/image-to-3d).
- Textures: `enable_pbr` adds metallic/roughness/normal (and emission on Meshy 6); `remove_lighting` (default true) "Removes highlights and shadows from the base color texture"; `hd_texture` gives 4K base colour; `image_enhancement` can be set false "to preserve the exact appearance of the input image without any style processing" — [Meshy image-to-3D API](https://docs.meshy.ai/en/api/image-to-3d), [Meshy API changelog](https://docs.meshy.ai/en/api/changelog).
- Scale/origin: `auto_size` "uses AI vision to automatically estimate the real-world height of the object and resize the model"; `origin_at` = `bottom` or `center` — [Meshy image-to-3D API](https://docs.meshy.ai/en/api/image-to-3d).
- UVs and parts: UV Unwrap API "Supports meshes of up to 40,000 faces (run Remesh first if larger); quad and n-gon meshes are triangulated during UV generation"; Auto Split API (9 Sep 2026) splits a model "automatically, by the parts you name (by_parts), or by color region (by_color)", but "the input's texture is not carried over and the result is an untextured model with one flat color per part" — [Meshy API changelog](https://docs.meshy.ai/en/api/changelog).
- Rigging/animation: "programmatic rigging currently only works well with standard humanoid (bipedal) assets"; "not suitable for … Untextured meshes, Non-humanoid assets, Humanoid assets with unclear limb and body structure"; inputs over 300,000 faces are rejected; the Animation API applies up to 10 preset actions and returns "a single file containing one animation clip per action, ready to drive from a state machine in a game engine"; Text to Motion added 21 Aug 2026 — [Meshy rigging API](https://docs.meshy.ai/en/api/rigging), [Meshy API changelog](https://docs.meshy.ai/en/api/changelog).
- Automation: REST API; official open-source MCP server `@meshy-ai/meshy-mcp-server` with tools such as `meshy_text_to_3d`, `meshy_image_to_3d`, `meshy_multi_image_to_3d`, `meshy_remesh`, `meshy_retexture`, `meshy_rig`, `meshy_animate`, `meshy_download_model`, `meshy_check_balance`; `llms.txt`/`llms-full.txt`; "every MCP tool call maps to a single REST call and consumes credits at the exact same rate" — [Meshy AI integration docs](https://docs.meshy.ai/en/api/ai), [meshy-mcp-server repo](https://github.com/meshy-dev/meshy-mcp-server). A CLI (`meshy-cli` 0.4.0, MIT, published 23 Sep 2026) has JSON output and stable exit codes — [npm registry: meshy-cli](https://registry.npmjs.org/meshy-cli); a skill pack for Claude Code/Codex/Cursor drives that CLI — [meshy-3d-agent repo](https://github.com/meshy-dev/meshy-3d-agent).
- API access and limits: "Free accounts can't create or manage their own API keys"; Pro and above get keys — [Meshy developer platform](https://docs.meshy.ai/en/api/developer-platform). Pro: 20 requests/s and 10 queued tasks — [Meshy rate limits](https://docs.meshy.ai/en/api/rate-limits). API-generated models "will only be retained for a maximum of 3 days" — [Meshy asset retention](https://docs.meshy.ai/en/api/asset-retention).
- Price: plans in the pricing page's structured data are Free (US$0, 100 credits/month), Pro US$20/month (1,000 credits), Premium US$40/month (3,000), Ultra US$100/month (8,000), Studio US$70/month (5,500 shared) — [Meshy pricing](https://www.meshy.ai/pricing). Credits per request: mesh only 20 (`meshy-7.1`/`meshy-6`) or 5 (`meshy-6-lite`/`meshy-t2`); image-to-3D with 2K textures 30 or 15; Ultra geometry +5; remesh 5; UV unwrap 5; auto-rigging 5; animation 3 per action — [Meshy API pricing](https://docs.meshy.ai/en/api/pricing). On fal.ai the same Meshy 7.1 costs US$0.80 untextured / US$1.20 textured, rigging +US$0.20 — [fal.ai Meshy 7.1](https://fal.ai/models/meshy/v7.1/image-to-3d).

Without a subscription, you can still download models generated by Meshy 6 Lite up to {count} times per month" (the count is a template variable) — [Meshy pricing](https://www.meshy.ai/pricing). #### Tripo — capabilities, automation, price, terms
- Polygon/topology control (v3.x): `face_limit` up to 1,500,000 triangles on v3.1 (2,000,000 in Ultra), quad up to 150,000; vendor guidance "Game-ready assets: 50,000 – 100,000. Web/mobile: 10,000 – 50,000"; `quad` forces FBX output; `smart_low_poly` produces "a low-poly model with hand-crafted, clean topology style. Best suited for simple, non-complex inputs. Complex models may occasionally fail", limited to 500–20,000 triangles or 500–10,000 quads — [Tripo image-to-model (standard)](https://developers.tripo3d.ai/en/docs/generation-image-to-model/standard).
- P series: `P1-20260311` `face_limit` 50–20,000; `P2-20260801` 48–50,000 triangles or 48–25,000 quads; "simple models start from 150 faces, complex models start from 250 faces. Lower values may result in poor generation quality" — [Tripo image-to-model (P series)](https://developers.tripo3d.ai/en/docs/generation-image-to-model/p). P1 "does not support quad, smart_low_poly, generate_parts, or geometry_quality" — [Tripo changelog](https://developers.tripo3d.ai/en/docs/changelog). Vendor claims for P1: it "delivers exceptionally refined geometry even at low face counts", produces a "Clean Low-poly Mesh", and takes about 10 s for an untextured base mesh (the China-region copy of the page adds about 60 s with texture); the model page gives the face range as 48–20,000 while the endpoint page says 50–20,000 — [Tripo P1 model page](https://developers.tripo3d.ai/en/models/p1), [Tripo P1 model page, cn mirror](https://developers.tripo3d.com/en/models/p1).
- Textures: PBR maps (`base_color`, `metallic`, `roughness`, `normal`); `texture_quality` fast/standard/detailed/extreme (8K); `delight` (default true, texture v3.5 only) "Removes baked-in lighting from the reference image before texturing" — [Tripo image-to-model (standard)](https://developers.tripo3d.ai/en/docs/generation-image-to-model/standard).
- Reproducibility: "Using the same seed with the same input will produce an identical 3D mesh" (`model_seed`); `texture_seed` likewise; dated model IDs can be pinned and the docs advise "Pin a specific model version to avoid output inconsistencies caused by model updates" — [Tripo image-to-model (standard)](https://developers.tripo3d.ai/en/docs/generation-image-to-model/standard), [Tripo models and versions](https://developers.tripo3d.ai/en/docs/models-and-versions).
- Scale/orientation/compression: `auto_size` scales "to real-world dimensions… in meters"; `export_orientation`; `compress: geometry` applies meshopt compression — [Tripo image-to-model (standard)](https://developers.tripo3d.ai/en/docs/generation-image-to-model/standard).
- Parts: `generate_parts` is "Not compatible with texture, pbr, quad, or smart_low_poly" — [Tripo image-to-model (standard)](https://developers.tripo3d.ai/en/docs/generation-image-to-model/standard). A separate segmentation endpoint has a geometry-based v1 and a semantic v2 "Beta" (`v2.0-20260430`) — [Tripo mesh segmentation](https://developers.tripo3d.ai/en/docs/mesh-segment).
- Retopology endpoint `POST /mesh/decimate`: "model=v2.0 (default) for smart highpoly-to-lowpoly retopology", target `face_limit`, optional `quad`, and `bake` (default true) "Bake textures onto the low-poly model" — [Tripo retopology](https://developers.tripo3d.ai/en/docs/mesh-decimate).
- Rigging/animation: rig model `v1.0-20240301` is "biped (humanoid) only… Supports 90+ animation presets"; `v2.5-20260210` handles "non-humanoid creatures (quadruped, hexapod, octopod, serpentine, aquatic, avian)"; `spec: mixamo` gives Mixamo-compatible bone names; output GLB or FBX — [Tripo auto rig](https://developers.tripo3d.ai/en/docs/animations-rig).
- Automation: REST v3; SDKs for JavaScript, Python, Go, Rust, Java; ComfyUI nodes; a Codex plugin — [Tripo docs index](https://developers.tripo3d.ai/llms.txt). Official `tripo-cli` (npm, MIT, v0.5.1 published 18 Sep 2026; used by VAST's own [Tripo3D-Plugin-dsh](https://github.com/VAST-AI-Research/Tripo3D-Plugin-dsh), whose README drives `npx tripo-cli make "..." --json --yes`): `npx tripo-cli make "a cute low poly fox"` writes `./tripo-out/<name>/{model.glb, preview.png, task.json}`; non-TTY runs are "automatically headless (--json --yes --no-open)"; `tripo batch run assets.yaml --concurrency 2` gives "batch with resume"; `tripo mcp` runs it "as an MCP server"; seeds and the wire model version are recorded in `task.json` — [npm registry: tripo-cli](https://registry.npmjs.org/tripo-cli). The older `tripo-mcp` repo is "in alpha", works through the Tripo Blender add-on and was last pushed 2025-04-14 — [tripo-mcp repo](https://github.com/VAST-AI-Research/tripo-mcp).
- Concurrency: default 10 concurrent H-series generations, 5 P-series, per account — [Tripo rate limits](https://developers.tripo3d.ai/en/docs/rate-limits).
- Price: the developer site states "1 credit = $0.01 USD" and "pay-as-you-go… 100 credits = $1.00 USD" — [Tripo API pricing](https://developers.tripo3d.ai/en/pricing). P2 costs "100 without texture; standard / detailed / extreme = 110 / 120 / 130" credits — [Tripo changelog](https://developers.tripo3d.ai/en/docs/changelog). P1 costs 30/40/50 credits (text) and 40/50/60 (image or multiview) for no/standard/detailed texture — [Tripo P1 model page](https://developers.tripo3d.ai/en/models/p1). On fal.ai, H3.1 image-to-3D is US$0.20 untextured, US$0.30 standard texture, US$0.40 HD texture, +US$0.20 detailed geometry, +US$0.05 quad; P2 is US$1.00–1.30 — [fal.ai H3.1](https://fal.ai/models/tripo3d/h3.1/image-to-3d), [fal.ai P2](https://fal.ai/models/tripo3d/p2/image-to-3d). ### Inferences
- **Which tiers can feed a public CC BY-SA repository** (reading of the quoted terms, not legal advice):
  - *Meshy paid*: yes — the customer owns the output and can choose the licence. Two obligations travel with it: do not strip Meshy's AI-identifying metadata or watermark (§2.4), and Meshy may train on non-Enterprise content (§2.9).
  - *Meshy free*: only as third-party material. Meshy owns it and licenses it CC BY 4.0; it can sit in a BY-SA project with attribution to Meshy, but it is not "the project's own asset" and cannot be relabelled CC0. In practice the free tier is also unusable for a pipeline: no API key and no downloads of Meshy 6/7 models.
  - *Tripo paid*: yes — paid users hold all rights including to "distribute… authorize and license". *Tripo free*: no — Tripo retains all rights and the plan is labelled non-commercial and public.
  - *Rodin*: the terms do not restrict use of Rodin output, and API output is private and deleted after 7 days; the plan table reserves "Unlimited export and any use" for paid plans, so treat paid as the safe case.
  - *Sloyd*: only on Pro (US$50/month); a public asset repository looks like the "redistribution" that Guest and Plus exclude.
  - *Hunyuan hosted*: no output-rights statement was found in the Tencent Cloud pages fetched, so it is unresolved.
- A pure prompt-or-image-to-mesh output may not be copyrightable at all in the US (Copyright Office position; Meshy's own disclaimer says output "MAY NOT QUALIFY FOR INTELLECTUAL PROPERTY PROTECTION"). CC BY-SA would then bind only the human-authored parts (concept art, cleanup, re-topology, material work, assembly). Creative Commons' own suggestion for low-human-input output is CC0. The project's existing rule to label generator and prompt fits this.
- The Meshy §2.4 "do not remove identifiers" clause could collide with a cleanup pipeline: re-exporting through Blender or glTF-Transform normally drops unknown metadata. Whether Meshy GLBs actually carry such metadata was not checked.
- Cost per kit is small next to labour. At US$0.30 (Tripo v3.1 textured) to US$0.60 (Meshy 7.1 textured at Pro rates) per attempt, 60 assets × 3 attempts is about US$54–108 per style and US$1,600–3,200 for 30 styles; Tripo P1 (US$0.40–0.60) and Hunyuan (US$0.50–0.70) land in the same band; Tripo P2 (US$1.00–1.30) is the outlier.
- Cheapest scriptable entry points for a solo developer: Meshy Pro (US$20/month includes API, MCP, CLI) and Tripo pay-as-you-go (US$0.01 per credit, CLI with batch/resume/seeds). Rodin's own API needs the US$120/month Business plan, so fal.ai (US$0.40) is the cheap route to Rodin — but fal's terms do not state who owns output and the vendor's own paid-tier terms would not obviously apply, so the rights position through a reseller is weaker than buying from Meshy or Tripo directly.
- Hosted model versions are retired quickly (Meshy 4 and 5 both gone within about a year; Tripo marks v3.0/v2.5 legacy). "Reproducible" therefore has to mean *committed output plus recorded prompt, seed, model ID and task record*, not regeneration on demand. Tripo is the only hosted service here that documents deterministic seeds; Meshy documents none.
- Nothing found offers a true voxel output mode: Meshy removed its text-to-voxel API in Oct 2025, and the others produce triangle meshes that merely look blocky. For the voxel and pixel-art packs, generating a normal mesh and voxelising it deterministically in Blender is likely to give more control than prompting for "voxel style".

- Tripo's `POST /v3/models/stylize` endpoint (formerly lego/voxel/Voronoi styles) exists in the v2→v3 mapping but its documentation page did not load, so current style options are unverified.
- Meta AssetGen: only the May 2025 announcement was found; its 2026 availability outside Horizon is unknown. CSM's status beyond "domain does not resolve" is unverified; an earlier search snippet described CSM as "Acquired, Active" without a retrievable source.

## 2. Open models: weight licences, VRAM, what runs on 8 GB, generation times

### Takeaway
On an 8 GB RTX 3070 Ti, **untextured or lightly textured geometry is realistic locally** (Hunyuan3D-2mini/2.0 shape, Stable Fast 3D, TripoSR, TripoSG, and TRELLIS.2 geometry through quantised GGUF builds), but **high-quality PBR texturing is not**: Hunyuan3D 2.1 texturing needs 21 GB, TRELLIS.2 officially needs 24 GB, SAM 3D needs 32 GB, and a user with an RTX 3070 8 GB reports that TRELLIS.2 texturing produces noise on that card. The licence picture is equally uneven: **TRELLIS.2 is MIT** (but its reference renderer dependencies are research-only), **the Hunyuan3D 2.0, 2.1 and Part licences forbid using, distributing or displaying the models' outputs outside a "Territory" that excludes the EU, UK and South Korea**, Stability's models are free below US$1M revenue, and **Roblox Cube is research-only**.

### Inferences
- A workable local split on this laptop is *geometry locally, texture elsewhere or by other means*: Hunyuan3D-2mini/2.0 shape (5–6 GB) or TRELLIS.2 geometry via trellis.cpp q4/q8 at 512, then flat/palette materials assigned in Blender for the low-poly, voxel and cel-shaded packs, which do not need a generated PBR texture at all. Full PBR texturing on 8 GB is the unreliable step; the one direct report on the same GPU family (Ampere, 8 GB) failed.
- The fastest/lightest models that fit 8 GB (SF3D, SPAR3D, TripoSR) date from 2024 and sit near the bottom of the human-preference ranking; they are fallbacks, not targets.
- For a globally reachable public repository, the Hunyuan licences are the hardest problem among open models: the prohibition covers "Output", includes output made "via a Hosted Service", and bars distribution or display outside a Territory that excludes the EU, UK and South Korea. A public GitHub repository is readable there. This is a licence-review blocker for *self-hosted* Hunyuan3D 2.x output regardless of where the developer sits. (Whether Tencent's own paid API output is under different terms is the gap noted in section 1.)
- TRELLIS.2 is the only top-tier open model with an unrestricted (MIT) weight licence. The C++ ports avoid the research-only nvdiffrast/nvdiffrec dependencies at runtime and add a CLI, an HTTP `/generate` endpoint and an optional quad-retopology stage with acceptance gates, which suits an agent-driven pipeline. They are young projects (created Jun–Jul 2026).
- Roblox Cube and CubePart are interesting technically (text + part list → separated meshes) but the research-only licence rules them out for shipped assets; SAM 3D targets real photographs and needs 32 GB.
- Renting a 24 GB cloud GPU by the hour or paying US$0.25–0.35 per TRELLIS.2 call on fal.ai is probably cheaper in time than fighting 8 GB, given kit sizes of 20–60 assets.

### Gaps
- No measured generation times or success rates on an 8 GB laptop GPU were found for any current model other than the single 3070 issue thread; all 8 GB feasibility here is from maintainer statements and issue reports, not tests.
- trellis.cpp does not state a minimum VRAM for the 512 path with q4/q8 weights on NVIDIA.
- The licence of the DINOv3 image encoder that the TRELLIS.2 pipelines load, and of BiRefNet background removal, was not reviewed.
- Whether Hunyuan3D 2.1 texturing can be made to fit 8 GB through ComfyUI offloading or quantised weights was not established (issue titles suggest fixes for 12–16 GB cards only).
- Stability's hosted 3D API prices could not be read (page did not render).

## 3. Keeping a whole kit in one style

### Takeaway
No generator offers a "style lock" for 3D on self-serve plans; the documented levers are **(a) feed every asset from a style-consistent 2D image rather than a text prompt, (b) add multi-view images, (c) re-texture all meshes against one style reference, and (d) pin model version and seeds**. Custom style training exists only as Sloyd "Custom Art Style" (plan feature, mechanics undocumented) and Rodin Enterprise "Custom LoRA and fine-tuning". No independent measurement of kit-level consistency was found.

### Cited Findings
- Meshy 7 is described in a competitor's summary of the launch as "a new image to 3D foundation model built around a single standard: the 3D result should agree with the image the user brought" (vendor positioning, relayed) — [Neural4D blog on Meshy 7](https://blog.neural4d.com/comparisons/meshy-7-release-date-and-alternative/). Meshy's API lets you switch off its own input restyling: `image_enhancement: false` "to preserve the exact appearance of the input image without any style processing" — [Meshy image-to-3D API](https://docs.meshy.ai/en/api/image-to-3d).
- Multi-view input: Meshy accepts "1 to 4 images… All images should depict the same object from different angles" and can chain from its own multi-view image task — [Meshy multi-image-to-3D API](https://docs.meshy.ai/en/api/multi-image-to-3d); its text-to-image endpoint has `generate_multi_view` and offers `nano-banana`, `nano-banana-2`, `nano-banana-pro`, `gpt-image-2` and GPT Image 2.5 models — [Meshy text-to-image API](https://docs.meshy.ai/en/api/text-to-image). Tripo: multiview-to-model takes front/left/back/right ("The front view cannot be omitted… at least 2 images are required… consistent lighting"), and `image-to-multiview` generates the four views from one image — [Tripo multiview-to-model](https://developers.tripo3d.ai/en/docs/generation-multiview-to-model/standard), [Tripo image-to-multiview](https://developers.tripo3d.ai/en/docs/generation-image-to-multiview). Hunyuan hosted accepts extra left, right and back views (and a top view on model 3.1) — [Tencent Cloud HY 3D Global API](https://www.tencentcloud.com/document/product/1284/75540). Rodin takes one to five images — [Rodin Gen-2.5 API](https://docs.hyper3d.ai/en/api-specification/rodin-gen2-5). Open: Hunyuan3D-2mv — [Hunyuan3D-2 README](https://github.com/Tencent-Hunyuan/Hunyuan3D-2); ComfyUI-Trellis2 multi-view generator and multi-view texturing nodes — [ComfyUI-Trellis2](https://github.com/visualbruno/ComfyUI-Trellis2).
- Style-reference texturing: Meshy Retexture takes exactly one of `text_style_prompt`, `image_style_url` or `multiview_image_urls`, with the caveat "Image texturing may not work optimally if there are substantial geometry differences between the original asset and uploaded image", and `enable_original_uv` to keep the existing UV layout — [Meshy retexture API](https://docs.meshy.ai/en/api/retexture). Tripo's texture endpoint accepts `{"text": "cyberpunk style", "style_image": {...}}` — "A reference image to influence artistic style" — [Tripo texture API](https://developers.tripo3d.ai/en/docs/models-texture).
- Seeds and pinning: Tripo `model_seed`/`texture_seed`/`image_seed` and dated model IDs; "Production environments: Pin a specific model version to avoid output inconsistencies caused by model updates" — [Tripo models and versions](https://developers.tripo3d.ai/en/docs/models-and-versions). Rodin `seed` 0–65535 — [Rodin Gen-2 API](https://docs.hyper3d.ai/en/api-specification/rodin-gen2). Meshy documents no seed — [Meshy text-to-3D API](https://docs.meshy.ai/en/api/text-to-3d).
- Shape control so pieces fit a kit: Rodin `bbox_condition` (maximum width/height/length) — [Rodin Gen-2 API](https://docs.hyper3d.ai/en/api-specification/rodin-gen2); Hunyuan3D-Omni accepts "point clouds, voxels, bounding boxes, and skeletal pose priors" — [arXiv 2509.21245](https://arxiv.org/abs/2509.21245); Roblox Cube v0.5 bounding-box conditioning — [Roblox/cube README](https://github.com/Roblox/cube); Stability Arbor's hull/avoidance/touch constraint meshes — [arXiv 2606.23514](https://arxiv.org/abs/2606.23514).
- Batch pipelines: `tripo batch run assets.yaml` with shared `defaults` (preset, post-processing chain, output folder), per-job overrides, and "State is saved next to the manifest (`assets.yaml.state.json`) after every job. Re-running the same command skips succeeded jobs (resume)" (bundled `skill/commands/batch.md`) — [tripo-cli 0.5.1 package tarball](https://registry.npmjs.org/tripo-cli/-/tripo-cli-0.5.1.tgz). Tripo presets encode a house style of parameters, e.g. `--for game-mobile` = "P1, face_limit 15000, 2K textures, convert to FBX" (bundled `skill/examples/game-asset.md`) — [tripo-cli 0.5.1 package tarball](https://registry.npmjs.org/tripo-cli/-/tripo-cli-0.5.1.tgz).
- Prompt-level style cues are the vendor's advice for text-to-3D: "Words like 'low poly', 'flat-shaded', 'faceted', and 'one color per face' steer the geometry and the texture. An image reference of an existing low poly asset locks the direction even harder." (vendor claim) — [Hyper3D low-poly page](https://hyper3d.ai/styles/low-poly).
- Custom style training: Sloyd Plus "1 Custom Art Style", Pro "Unlimited Custom Art Styles" — [Sloyd pricing](https://www.sloyd.ai/pricing); Rodin Enterprise "Custom LoRA and fine-tuning" — [Hyper3D pricing](https://hyper3d.ai/pricing?lang=en). TRELLIS.2 and Hunyuan3D 2.1 publish training code, so fine-tuning is possible in principle — [TRELLIS.2 README](https://github.com/microsoft/TRELLIS.2), [arXiv 2506.15442](https://arxiv.org/abs/2506.15442).
- Human raters reward presentation over structure: "textured models receiving a 144.1 ELO advantage over untextured models" — [3D Arena paper, arXiv 2506.18787](https://arxiv.org/abs/2506.18787).

### Inferences
- Because Agentnagar already has per-style concept sheets from one image generator, image-to-3D from crops of those sheets is the natural consistency mechanism: style is fixed upstream in 2D, where control is best, and the 3D model is asked only to lift it.
- Geometry style (facet size, bevels, proportions) and surface style (palette, outlines, shading) should be separated. Geometry consistency comes from one generator, one model version, one face budget per asset class; surface consistency is more reliably imposed afterwards — a shared palette texture, flat materials, a cel shader or outline pass in Godot — than requested from the generator. For low-poly, voxel, cel-shaded and pixel-art packs this means generated PBR textures can often be discarded, which also removes the weakest local step (section 2).
- A style change at the engine level (the project's live pack switching) suggests generating one *neutral* mesh per object and deriving several packs from it by scripted restyling (decimate, voxelise, palette-map, re-texture with a style image) rather than generating 30 independent kits. This is a hypothesis to test, not a documented practice.
- Mixing generators inside one kit is likely to show: each has its own topology density, texel density and bake look.

### Gaps
- No practitioner write-up, benchmark or video measuring style consistency across a 20–60 piece kit was found; LoRA-based workflows for 3D kits and style-locked image generation pipelines (for example Scenario-style trained models feeding 3D) could not be researched without search. The one Scenario help page fetched describes a Meshy pipeline but gives no consistency guidance — [Scenario: Meshy essentials](https://help.scenario.com/articles/5709143930-meshy-the-essentials).
- How well style-reference retexturing holds a palette across many meshes is undocumented.

## 4. Concept sheet to asset: workflow, and buildings versus props versus characters

### Takeaway
The individual steps are all documented and scriptable — clean single-object image → (optional) multi-view → image-to-3D with a face budget → scale/origin normalisation → decimate/retopology with texture bake → format conversion — and both Meshy and Tripo expose most of them as API parameters. **No end-to-end published workflow for cutting an AI concept sheet into objects was found**, and **no independent test of buildings/architecture versus props versus characters was found**; what exists are vendor hints that hard-surface props are the strongest case, organic shapes and non-humanoid rigs the weakest, and a general rule that single-view input leaves the back and interior to be invented.

### Cited Findings
- Input requirements (vendor docs): "The subject should be clearly visible with minimal occlusion… clean background"; PNG/JPEG/WebP; at least 256 × 256 px — [Tripo image-to-model (standard)](https://developers.tripo3d.ai/en/docs/generation-image-to-model/standard). Background removal is built into the open pipelines (BiRefNet in trellis.cpp and TripoSplat) — [trellis.cpp README](https://github.com/pwilkin/trellis.cpp), [TripoSplat model card](https://huggingface.co/VAST-AI/TripoSplat).
- Chaining image generation into 3D inside one API: Tripo's `input` can be "The task ID from a previous image generation task"; Meshy's `input_task_id` accepts a completed Text to Image or Image to Image task — [Tripo image-to-model (standard)](https://developers.tripo3d.ai/en/docs/generation-image-to-model/standard), [Meshy multi-image-to-3D API](https://docs.meshy.ai/en/api/multi-image-to-3d).
- A scripted recipe from the vendor, including LODs from one source: `tripo make "a stone golem" --for game-pc --then decimate:5000` ("bakes normals by default") followed by `tripo make @last --then decimate:1500,convert:fbx`; character chain "rig-check → rig(v2.5 rig) → retarget(idle+walk)" (bundled `skill/examples/game-asset.md`) — [tripo-cli 0.5.1 package tarball](https://registry.npmjs.org/tripo-cli/-/tripo-cli-0.5.1.tgz).
- Meshy's five-step pipeline as relayed by a third-party platform: "create the base asset with Meshy 7.1… run Meshy Remesh to bring the mesh to an engine-friendly poly count… UV Unwrap… Retexture… auto-rig with Meshy Rigging, then animate" with the warning "keep the input mesh under about 300K polygons for Rigging; heavier meshes take significantly longer and far more likely to fail" — [Scenario: Meshy essentials](https://help.scenario.com/articles/5709143930-meshy-the-essentials).
- Scale and origin: Meshy `auto_size` + `origin_at: bottom`; Tripo `auto_size` (metres) and `export_orientation`; Meshy rigging takes `height_meters` (default 1.7) — [Meshy image-to-3D API](https://docs.meshy.ai/en/api/image-to-3d), [Tripo image-to-model (standard)](https://developers.tripo3d.ai/en/docs/generation-image-to-model/standard), [Meshy rigging API](https://docs.meshy.ai/en/api/rigging).
- Scene-level alternatives that take one image containing several objects and return separate object meshes with poses (research code, Sept 2026): Mira-Scene "reconstructs an editable 3D scene from a single image" via instance segmentation, depth, per-object mesh generation and scene assembly (MIT) — [Mira-Scene repo](https://github.com/VAST-AI-Research/Mira-Scene); Fire3D predicts "object-level 6-DoF pose, bounding box, mesh geometry, and texture" from one RGB image — [Fire3D model card](https://huggingface.co/hongchi/Fire3D); fal.ai's SAM 3D endpoint returns `individual_glbs` per object — [fal.ai SAM 3D](https://fal.ai/models/fal-ai/sam-3/3d-objects).
- Buildings and hard-surface (all vendor or vendor-adjacent statements):
  - Rodin tier guidance: `Gen-2.5-Low` for "Clean assets and small hard-surface props" — [Rodin Gen-2.5 API](https://docs.hyper3d.ai/en/api-specification/rodin-gen2-5).
  - An affiliate-linked review: Rodin "Organic shapes...weaker than hard-surface objects"; complex prompts merge incorrectly "in roughly 2 out of 5 generations" (cites other reviews rather than its own test) — [dupple Rodin review](https://dupple.com/reviews/rodin-ai).
  - A Godot-tool vendor's blog: Tripo handles "hard-surface mechanical assets noticeably better"; Rodin "beats Meshy and Tripo on organic and stylized character output"; Sloyd output is "consistently low-poly (1k-15k triangles), correctly UV-mapped, and rigging-ready" (3 Jun 2026; no test data shown) — [Ziva blog](https://ziva.sh/blogs/best-ai-3d-asset-generators).
  - A hosting vendor's comparison (31 May 2026, no controlled test inputs): for topology it puts "Tripo v3.1 with Quad Mesh" first, then Rodin 2.0 quad mode, then Meshy 6 with quad remesh; for PBR it prefers Meshy 6 on photographic input, Hunyuan 3D 3.1 on illustrative input and Rodin 2.0 on hard-surface; Hunyuan 3D 3.1 "Topology is acceptable for static props but needs a Blender retopology pass before rigging" — [Sorceress six-model comparison](https://sorceress.games/blog/rank-the-best-image-to-3d-model-ai-six-model-test).
- Representation matters for architecture and plants: TRELLIS.2's O-Voxel "can robustly model arbitrary topology, including open, non-manifold, and fully-enclosed surfaces"; the README lists "Open Surfaces (e.g., clothing, leaves)", "Non-manifold Geometry" and "Internal Enclosed Structures" as handled, and models "Base Color, Roughness, Metallic, and Opacity" (authors' claims) — [arXiv 2512.14692](https://arxiv.org/abs/2512.14692), [TRELLIS.2 README](https://github.com/microsoft/TRELLIS.2). A deliberately tiny 32³ text-to-voxel model reports plainly: "It works for bulky objects and it fails for thin ones" — [VoxelModel v1 card](https://huggingface.co/bench-labs/VoxelModel-v1). UltraShape's data pipeline includes "thickening thin structures" — [UltraShape model card](https://huggingface.co/infinith/UltraShape).
- Characters: A/T-pose flags (Meshy `pose_mode`, Rodin `TAPose`); Meshy rigging humanoid-only; Tripo rig v2.5 for quadrupeds and other creatures; a vendor-adjacent blog says "Auto-rigging works on clean humanoid meshes and falls apart on anything unusual" — [Meshy text-to-3D API](https://docs.meshy.ai/en/api/text-to-3d), [Rodin Gen-2 API](https://docs.hyper3d.ai/en/api-specification/rodin-gen2), [Tripo auto rig](https://developers.tripo3d.ai/en/docs/animations-rig), [Summer Engine blog](https://www.summerengine.com/blog/ai-3d-game-asset-generator).
- Low-poly budget guidance (vendor): "Under 5K faces reads as unmistakably low poly and runs anywhere"; "5–20K is the normal band for mobile and stylized game assets"; "a humanoid at 500 faces loses its hands before it loses its silhouette" — [Meshy low-poly page](https://www.meshy.ai/features/low-poly).

### Inferences
- A concept *sheet* is the wrong unit of input: every documented generator wants one object, unoccluded, on a clean background. The sheet has to be split first (segmentation plus background removal), or the image generator should be asked to emit one object per image in the locked style. Asking the same image model for a matching back or three-quarter view before 3D generation is the cheap way to stop the generator inventing the hidden side — which matters most for buildings, whose rear and side façades carry design.
- Buildings are the asset class least well served: they are large, must sit on a grid, need consistent storey heights and door positions, and have no interiors unless modelled. Generators return a single watertight shell with façade detail fused into it. A hybrid is more plausible for a city kit — keep the scripted Blender generator for footprint, storeys and snapping, and use AI generation for the *dressing* (roofs, doors, signage, awnings, props, plants) and for hero landmarks. This is the researcher's judgement; no source tests it.
- Bounding-box and hull conditioning (Rodin, Hunyuan3D-Omni, Arbor) are the only documented ways to make a generated piece respect a modular footprint.
- Props and vegetation with solid volumes are the low-risk category; thin foliage, railings, wires and lattice are the high-risk one and are better built from cards or procedural geometry.

### Gaps
- No documented, reproducible workflow for "AI concept sheet → cropped objects → image-to-3D → cleanup" was found, and no independent comparison of buildings/architecture against props and characters. Both are the main open questions for a pilot.
- Whether current generators reproduce a flat-shaded, low-facet concept faithfully or "improve" it into dense detail was not measured anywhere found (Meshy's `image_enhancement` flag suggests the default behaviour restyles the input).

## 5. Game-readiness: typical defects, cleanup tools, and what practitioners report (Godot)

### Takeaway
The vendors' own parameters are a checklist of the known defects — baked lighting (`remove_lighting`, `delight`), arbitrary scale and origin (`auto_size`, `origin_at`), dense triangle soup (remesh, Smart Topology, P-series, retopology endpoints), missing or poor UVs, single fused meshes (part-splitting endpoints) and humanoid-only rigging — and most now have a scripted remedy. What remains manual is collision, material fit to the engine's lighting, retopology for deforming characters ("no perfect automatic tools exist"), and inspection for broken or floating geometry. **Evidence from shipped Godot games is almost absent**: the only concrete Godot case found is Meshy's own tutorial.

### Cited Findings
- Defects implied by documented fixes:
  - Baked-in lighting: Meshy `remove_lighting` "Removes highlights and shadows from the base color texture, producing a cleaner result that works better under custom lighting setups"; Tripo `delight` "Removes baked-in lighting from the reference image before texturing" (only on texture model v3.5, Sep 2026) — [Meshy image-to-3D API](https://docs.meshy.ai/en/api/image-to-3d), [Tripo changelog](https://developers.tripo3d.ai/en/docs/changelog).
  - Density: Meshy 7.1 raw meshes reach "up to 80 million triangles before simplification" (vendor) — [Meshy 7.1 launch post](https://www.meshy.ai/blog/meshy-7-1-launch); Hunyuan hosted defaults to 500,000 faces — [Tencent Cloud HY 3D Global API](https://www.tencentcloud.com/document/product/1284/75540); TRELLIS.2's example exports with `decimation_target = 1000000` and a 4096 texture — [TRELLIS.2 README](https://github.com/microsoft/TRELLIS.2); fal.ai's sample Hunyuan output GLBs are about 38.6 MB (v3.1 Pro) and 64.1 MB (v3) — [fal.ai Hunyuan 3D v3.1 Pro](https://fal.ai/models/fal-ai/hunyuan-3d/v3.1/pro/image-to-3d), [fal.ai Hunyuan3D v3](https://fal.ai/models/fal-ai/hunyuan3d-v3/image-to-3d).
  - Scale: "Generators output models at arbitrary sizes. Drag one into a scene and it might be the size of a building or a grain of rice." (vendor blog, 6 Jun 2026) — [Summer Engine blog](https://www.summerengine.com/blog/ai-3d-game-asset-generator).
  - Materials: "In your engine they can read flat, too shiny, or too dark, because your renderer's lighting and color space differ"; "A visual mesh does nothing physically. The player walks through it."; the "import-scale-collide-rig loop" is "where most of the actual time goes" — [Summer Engine blog](https://www.summerengine.com/blog/ai-3d-game-asset-generator).
  - Single material slot: "Generated assets ship with a single material slot 90% of the time. If your shader expects separate material indices… split the mesh in Blender before import." (vendor blog, unquantified source) — [Ziva blog](https://ziva.sh/blogs/best-ai-3d-asset-generators).
  - Non-manifold/holes: "STL exports for 3D printing often need repair for non-manifold edges" (Rodin, review) — [dupple Rodin review](https://dupple.com/reviews/rodin-ai); the ComfyUI TRELLIS.2 wrapper ships several hole-filling and "Weld Vertices" nodes — [ComfyUI-Trellis2](https://github.com/visualbruno/ComfyUI-Trellis2).
  - Failure modes admitted in a vendor tutorial: one broken Smart Topology mesh that was fixed by retrying, and one "stray floating quadrant" that was deleted by hand in Blender — [Meshy Godot tutorial](https://www.meshy.ai/tutorials/create-3d-game-in-godot).
  - Split parts lose their textures: Meshy Auto Split returns "an untextured model with one flat color per part"; Tripo `generate_parts` cannot be combined with texture — [Meshy API changelog](https://docs.meshy.ai/en/api/changelog), [Tripo image-to-model (standard)](https://developers.tripo3d.ai/en/docs/generation-image-to-model/standard).
  - Uniqueness: both Meshy and Tripo disclaim that different users may receive similar or identical output — [Meshy terms](https://www.meshy.ai/terms-of-use), [Tripo terms](https://www.tripo3d.ai/terms).
- Hosted cleanup endpoints: Meshy Remesh (quad or triangle, 100–300,000 faces, regenerates UVs: "Textures are re-applied against the new UVs" — vendor), UV Unwrap, Resize, Convert; Tripo Retopology v2.0 with texture bake and per-part decimation, Convert (GLTF, FBX, USDZ, OBJ, STL, 3MF); Tencent "Smart Topology" (50 credits) — [Meshy remesh API](https://docs.meshy.ai/en/api/remesh), [Meshy low-poly page](https://www.meshy.ai/features/low-poly), [Tripo retopology](https://developers.tripo3d.ai/en/docs/mesh-decimate), [Tripo docs index](https://developers.tripo3d.ai/llms.txt), [Tencent HY 3D Global billing](https://www.tencentcloud.com/document/product/1284/75281).
- Local cleanup tools:
  - Blender 5.2 LTS manual: the Decimate modifier "allows you to reduce the vertex/face count of a mesh with minimal shape changes" — [Blender manual: Decimate](https://docs.blender.org/manual/en/latest/modeling/modifiers/generate/decimate.html). Voxel remesh gives "uniform topology and has no inner (self-intersecting) geometry" but should not be used for "a mesh that will be deformed (e.g. a character that will be animated). Such topology has to follow the flow of the geometry, and no perfect automatic tools exist for this right now; it has to be done manually"; the Quad remesher "uses the Quadriflow algorithm" and "doesn't clean up intersecting geometry" — [Blender manual: Remeshing](https://docs.blender.org/manual/en/latest/modeling/meshes/retopology.html).
  - glTF-Transform CLI: `weld`, `simplify`, `resize`, `webp`/`avif`, `uastc`/`etc1s` (KTX2), `draco`, `meshopt`, `dedup`, `prune`, and a combined `optimize` whose "Defaults… may not be ideal for all scenes" — [glTF-Transform CLI](https://gltf-transform.dev/cli).
  - trellis.cpp ships `tools/glb_metrics.py` ("components, boundary edges, winding, texel density") and a quad-retopology path where "The requested GLB is published only after the geometry, topology, source-cover, exact-UV, and bake gates pass" — [trellis.cpp README](https://github.com/pwilkin/trellis.cpp).
  - Open auto-rigging: UniRig ("One Model to Rig Them All", MIT) and SkinTokens (MIT) — [VAST-AI-Research repositories](https://github.com/VAST-AI-Research).
- Godot side (Godot 4.7 docs): glTF 2.0 is the "(recommended)" format — [Godot: available 3D formats](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html). LODs are generated automatically on import for glTF, .blend, Collada and FBX using meshoptimizer, on by default, though the process "may occasionally introduce rendering issues (especially in skinned meshes)" and "can also take a while on complex meshes" — [Godot: mesh LOD](https://docs.godotengine.org/en/stable/tutorials/3d/mesh_lod.html). Node-name suffixes create collision at import: `-col` (static trimesh child), `-convcol` (convex), `-colonly`, `-convcolonly`; `-navmesh` converts a mesh to a navigation mesh — [Godot: node type customization](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/node_type_customization.html).
- Godot's glTF importer source on `master` (checked 2026-10-01, 42 source files under `modules/gltf`, `structures` and `editor`) contains no reference to Draco or meshopt compression; the extensions it names are `KHR_texture_basisu` and `EXT_texture_webp` (texture extension classes) plus `KHR_texture_transform`, `KHR_lights_punctual`, `KHR_materials_emissive_strength`, `KHR_materials_unlit`, `KHR_materials_pbrSpecularGlossiness`, `KHR_animation_pointer` and `KHR_node_visibility` — [Godot glTF module source](https://github.com/godotengine/godot/tree/master/modules/gltf).
- Godot practice reports (all vendor-authored):
  - Meshy's tutorial (15 Sep 2026) describes "Paintful", a Godot 3D platformer-shooter in which the character, paint blaster, slime enemies, turrets and floating platforms were all generated with Meshy and nothing was modelled by hand; export is a single GLB, and all animations arrive in one AnimationPlayer inside it; Smart Topology default about 4,000 faces; character remeshed to roughly 10,000 faces; no account of scale, collision or AnimationTree work — [Meshy Godot tutorial](https://www.meshy.ai/tutorials/create-3d-game-in-godot).
  - "The default 'Scene' import settings work for Meshy, Tripo, Rodin, and Hyper3D output"; "Sloyd output sometimes needs 'Reset' on the mesh import to clear stale lightmap UV2 channels" — [Ziva blog](https://ziva.sh/blogs/best-ai-3d-asset-generators). The same post advises "use Godot's built-in GLTF compression (Draco) on the import step"; this is contradicted by the engine source (see the Godot importer check above).
  - "You still set up materials and collision in Godot after import" — [3D AI Studio blog](https://www.3daistudio.com/blog/best-ai-tools-for-godot-2026).
  - A comparison page from another vendor states that it "does not claim that an AI-generated mesh is automatically game-ready, printable, riggable, or ready for manufacturing" (12 Jul 2026) — [Blyth blog](https://blyth.ai/blog/best-ai-3d-model-generators-2026).

### Inferences
- The project already has the right backbone: headless Blender scripts that export GLB. The same scripts can become the *normaliser* for generated meshes — import GLB, drop loose islands below a size threshold, recentre origin to the base, rescale to a catalogue height, decimate to a per-class budget, optionally voxelise or flat-shade, replace or palette-map materials, name collision proxies with `-col`/`-convcol`, export — with glTF-Transform as a final weld/prune/texture-resize step. Each step is deterministic and can be validated by metrics (face count, component count, bounding box, texture size) before a commit.
- Because the Godot importer shows no Draco or meshopt support, the glTF optimisation step should stop at weld, simplify, prune and texture resizing/re-encoding (WebP or KTX2), and Tripo's `compress: geometry` (meshopt) option should be left off for assets headed to Godot.
- For crowds, the budget is a design decision the generators can meet directly: Tripo P1/P2 (48–20,000 / 50,000 faces), Meshy Smart Topology (100–15,000) and Rodin quad presets (4,000–50,000) generate at the target instead of decimating after the fact, and Godot adds automatic LODs for glTF. Texture memory, not triangles, is the more likely limit if every asset carries its own 2K–4K PBR set; shared palette textures avoid that.
- Human time per asset will be dominated by *inspection and rejection*, not generation: expect to regenerate rather than repair, since repairs are manual and generations cost cents. The Meshy tutorial's two admitted failures in a small demo suggest a non-trivial reject rate even in a vendor's showcase.
- Characters remain the costly class: automatic rigging is reliable only for clean bipeds, and deforming topology still needs human retopology according to the Blender manual. A few characters per style is manageable by hand; dozens would not be.

### Gaps
- No independent post-mortem, devlog or forum thread from a developer who shipped a Godot game with AI-generated 3D assets could be retrieved (search unavailable for Reddit, YouTube, 80.lv, CG Channel). Reject rates, minutes of cleanup per asset and frame-rate outcomes are therefore unquantified.
- The Godot source check above was a text scan of the importer on `master`, not an import test on Godot 4.6/4.7 release builds; which texture formats (KTX2/Basis, WebP) import cleanly on the project's export targets was not tested.
- Whether generated GLBs embed AI-provenance metadata, and whether Godot or Blender preserve it, was not checked.

## 6. Environment and world generators (brief; only what is new or practical)

### Takeaway
Nothing changes the earlier conclusion: world generators give you a single baked scene (splats plus a coarse collider mesh), not a kit of reusable, restylable assets. **Marble's collider and high-quality mesh GLBs are ordinary glTF and so can in principle be imported into Godot as a walkable static scene**, but no Godot-specific workflow is documented. New since the project's September review are research systems that output *separate object meshes* for a scene (Tencent WorldClaw, VAST Mira-Scene, Fire3D), none of them a product.

### Cited Findings
- Marble exports are unchanged: splats (SPZ/PLY, about 2M or 500k), a "coarse mesh optimized for simple physics calculations" (collider GLB, 100–200k triangles), and a high-quality mesh GLB (about 600k triangles textured or about 1M with vertex colours, taking up to one hour, "rate limited to 4 generation requests per hour per user"); worlds use OpenCV coordinates, so Y and Z must be flipped for OpenGL-style software — [Marble export specs](https://docs.worldlabs.ai/marble/export/specs). API prices: US$1.00 per 1,250 credits; world generation 1,500 credits (US$1.20), Marble 1.1 Plus up to US$2.48; high-quality mesh export 3,500 credits (US$2.80) per world; PLY export free (page data through 25 Jun 2026) — [World Labs API pricing](https://docs.worldlabs.ai/api/pricing).
- HY-World 2.0: news entry "[July, 2026]: Update HY World 2.1! Try our product"; open components are WorldMirror 2.0, HY-Pano 2.0, WorldStereo 2.0 and the generation pipeline; README claims outputs are "Directly importable into Blender / UE / Isaac Engine" with "first-person navigation and third-person character mode… with physics-based collision"; the pipeline builds a Recast navmesh extension — [HY-World 2.0 README](https://github.com/Tencent-Hunyuan/HY-World-2.0). Its licence carries the same EU/UK/South Korea exclusion for the works and their output — [HY-World 2.0 licence](https://github.com/Tencent-Hunyuan/HY-World-2.0/blob/main/License.txt).
- New (Aug 2026): Tencent **WorldClaw**, "a fully agentic, coarse-to-fine framework for open-world 3D scene generation" in which planning agents produce "a structured specification of regions, terrain, assets, materials, and spatial relations" and the result has "editable instance-level assets"; the repository contains only the paper and project-page links — [arXiv 2608.05248](https://arxiv.org/abs/2608.05248), [WorldClaw repo](https://github.com/Tencent-Hunyuan/Hunyuan3D-WorldClaw).
- New (Sep 2026): **Mira-Scene** (single image → editable scene of object meshes; "fully open-source", MIT) and **Fire3D** ("simulation-ready 3D scene assets" from one image or casual video) — [Mira-Scene repo](https://github.com/VAST-AI-Research/Mira-Scene), [Fire3D model card](https://huggingface.co/hongchi/Fire3D).
- Meta WorldGen (Nov 2025) generates 50 × 50 m navigable scenes with navmesh, "Compatible with standard game engines including Unity and Unreal", but is "not available to developers" — [Meta WorldGen post](https://www.meta.com/blog/worldgen-3d-world-generation-reality-labs-generative-ai-research/).
- Godot can turn an imported mesh into static collision or a navigation mesh by naming convention (`-col`, `-colonly`, `-navmesh`) — [Godot: node type customization](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/node_type_customization.html).

### Inferences
- A Marble world is usable in Godot today only as a one-off backdrop or exhibit room: import the HQ mesh GLB for visuals and the collider GLB with a `-colonly` suffix for physics. It cannot be switched between style packs, has baked lighting and no object separation, and each export costs US$2.80 on top of generation.
- The scene-decomposition research (Mira-Scene, Fire3D, WorldClaw) points at what the project actually wants — a layout plus separate assets — but is weeks to months old and unproven outside papers.

### Gaps
- No documented Godot import of Marble, HY-World or Genie-class output was found; Genie-class models were not re-examined (no change known since the project's earlier review).
- VRAM requirements for the HY-World 2.0 generation pipeline are not stated in its README.

## 7. Independent evidence: leaderboards, comparisons, candid reviews

### Takeaway
The one open, methodologically documented benchmark (Hugging Face **3D Arena**, with separate render and wireframe-topology boards) is useful for the open models but **does not include current Tripo, Rodin or Hunyuan 3.x**, and its main board structurally favours textured and splat outputs. Every comparison article retrieved was written by a vendor or an affiliate site and contained no controlled test. **Candid practitioner evidence is the weakest part of this research** and should be replaced by a small paid pilot.

### Cited Findings
- 3D Arena method: pairwise human votes on image-to-3D results from a fixed set of 100 prompts (the iso3d dataset); the paper reports 123,243 votes from 8,096 users across 19 models, 99.75% user authenticity, and presentation bias — "Gaussian splat outputs achieving a 16.6 ELO advantage over meshes and textured models receiving a 144.1 ELO advantage over untextured models" — and recommends "multi-criteria assessment, task-oriented evaluation, and format-aware comparison" — [arXiv 2506.18787](https://arxiv.org/abs/2506.18787). The site itself says "there is no standard practice for reporting critical factors like mesh topology in real-world applications" and requires models to "run end-to-end without human intervention, including UV unwrapping, texture mapping" — [3D Arena space](https://huggingface.co/spaces/3d-arena/3d-arena).

### Inferences
- The Arena result that TRELLIS.2-4B (1126) sits far below the older TRELLIS (1304) and its splat variant (1399) contradicts the paper's claim of superiority. Possible explanations are the documented presentation bias, export settings of the submitted meshes, or genuine weakness on this prompt set; the data cannot distinguish them. It is a reason not to assume the newest open model is the best for stylised objects.
- Of the four hosted services profiled in section 1, only Meshy has Arena entries; Meshy-6 ranks third on both the render and the topology boards, and Meshy-7 has too few votes (164 and 133) to read. On the topology board the older open models (Hunyuan3D-2, TRELLIS v1, Hunyuan3D-2.1) lead and TRELLIS.2-4B is again mid-table (11th), so on this prompt set the newest open model wins neither on looks nor on wireframe preference.
- The topology board measures which wireframe people prefer when zoomed in, on raw generator output. It is the closest thing found to independent topology evidence, but it has few votes per model and does not test the hosted low-poly modes (Tripo P1/P2, Meshy Smart Topology, Rodin quad) that matter most for a low-poly kit.
- Because the published comparisons judge beauty shots, they say little about what this project needs — faithful low-facet geometry, clean silhouettes at 2–15k faces, consistent texel density, and behaviour on buildings. Those criteria can only be scored by generating the same 8–10 objects from one of the project's own concept sheets with two or three services (roughly US$20–60 in credits) and inspecting wireframes in Blender and frame time in Godot.

### Gaps
- Not retrieved for lack of search: Reddit threads (r/StableDiffusion, r/gamedev, r/godot, r/blender, r/3Dmodeling), YouTube side-by-side tests, 80.lv and CG Channel coverage of Meshy 7, Tripo P1/P2, Hunyuan 3.x and Rodin Gen-2.5, and any academic benchmark newer than the 3D Arena paper. (Tencent's HY3D-Bench, Feb 2026, turned out to be a set of training datasets — "252K+ watertight meshes", a part-level set and a synthetic set — not a model comparison: [HY3D-Bench repo](https://github.com/Tencent-Hunyuan/HY3D-Bench).)
- Large-vendor entrants (Autodesk, Adobe, Google, NVIDIA, Unity/Epic built-in generators) were not checked.
- No independent evaluation of topology quality (quad flow, pole placement, UV islands) for Tripo, Rodin or Hunyuan 3.x was found; the Arena's topology board covers only Meshy among the hosted services and says nothing about UVs.
- No source quantified reject rates or cleanup minutes per asset for stylised kits.
